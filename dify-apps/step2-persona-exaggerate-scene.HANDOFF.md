# Step 2（人设 + 夸张反差 + 场景）Dify 导入后配置清单

本 workflow 依赖一个真实知识库（检索 51 条人设方法论原子）与真实 LLM 模型，导入后需完成
以下配置才能正常运行。未配置时，检索节点返回 0 个候选，`code_validate_persona` 会以显式
`[retrieval]` 错误失败——这是设计好的显式报错链路，不是隐藏问题；它也验证了「引用必须真实
存在」这条机械校验在真实 Dify 环境里确实生效。

## 第一步：创建知识库并上传 51 条人设原子

1. Dify 左侧导航进入「知识库」，点击「创建知识库」。
2. 选择「导入已有文本」/「从文件导入」，把 `dify-apps/kb-seed-persona-patterns/` 目录下全部
   51 个 `.md` 文件一次性拖入（Dify 支持批量多文件上传）。
3. 分段设置建议选「父子分段」或调大分段长度。每个原子文档开头有一段紧凑的
   `PATTERN_NAME:` / `AVOID_WHEN:` / `COMPLIANCE_RISKS:` 标记块，故意放在标题正下方，就是为了
   在默认分段设置下也大概率落进第一个分段——分段切得太碎会增加这块标记没被检索到的概率。
4. Embedding 模型选工作区里已装好的任意一个，不影响校验逻辑本身。
5. 等索引状态变为「可用」。

## 第二步：把检索节点接到这个真实知识库

1. 打开 workflow，点开检索节点（对应画布里的 `kb_retrieve_persona_patterns`）。
2. 在右侧配置面板的知识库选择器里，勾选刚建好的那个知识库。
3. `top_k` 保持 3 不用改。

## 第三步：确认三个 LLM 节点都换过真实模型

导入后三个 LLM 节点默认都是占位的 `gpt-4o-mini`，需逐个点开确认换成真实模型（Dify 不会跨
节点自动同步模型选择）：

- `llm_generate_persona`（Stage A · 生成人物设定）
- `llm_generate_exaggerate`（Stage B · 生成夸张点 + 反差）
- `llm_generate_scene`（Stage C · 生成场景）

## 第四步：重新测试运行

1. 把测试脚本内容粘进 `source_script` 输入框。
2. 期望结果：人物阶段应引用真实存在的中文方法论名字（如「权威去污名痛点中断」这类），
   不应出现编造的英文短语——若仍编出英文名字，说明检索没接对，回第二步排查。
3. 若检索确认接对但仍失败，大概率是分段切得太碎导致 `PATTERN_NAME` 那行被拆进了未检索到的
   分段，回第一步调整分段设置并重新导入知识库。
