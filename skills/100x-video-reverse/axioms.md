# 100x-video-reverse · 核心约束

本文件只记录能改变交接结论的硬约束。视觉理解是否准确仍需对照源视频人工或多模态复核，不能由格式验证器冒充。

## 公理 1：源文件只读且证据绑定哈希

**一句话**：源视频只读，证据必须绑定源哈希。

**可机器验证断言**：

- `prepare_evidence.py` 只读取源视频，在新目录写入 `source_manifest.json`，记录 SHA-256 与媒体规格。
- `materialize_reverse_media.py` 和 `validate_reverse_package.py` 比较源哈希、请求时间戳与媒体哈希；任一不一致即硬错误。
- `scripts/validate.js` 负责公开 JSON 契约的结构和引用校验；文件系统及哈希校验由 Python 严格验证器负责。

**出处**：首轮同样本实验发现，反馈修改后复用同路径旧截图会造成“文件存在但证据已漂移”。本规则为本次实验提炼。

**反例（作废条件）**：源哈希变化后仍复用旧媒体，或向非空输出目录覆盖写入，必须 FAIL。

## 公理 2：镜头连续覆盖真实时间轴

**一句话**：镜头连续覆盖全片，不留缝不重叠。

**可机器验证断言**：

- `schema.json` 约束镜头、四类关键帧、动作和证据字段必须存在。
- `scripts/validate.js` 检查首镜从 0 开始、末镜对齐视频时长、相邻镜头连续、`duration=end-start`、关键帧和证据时间戳位于镜头区间。
- 自动检测结果只能写作 `cut_proposals`，不能直接声明为真实镜头边界；语义正确性需要回看源视频。

**出处**：双阈值场景变化与均匀采样的组合实验；单阈值会漏掉闪切和快速商品动作。

**反例（作废条件）**：时间轴存在空隙、重叠、倒序、零时长，或关键帧落在镜头区间之外，必须 FAIL。

## 公理 3：镜头、资产和提示词引用闭合

**一句话**：镜头、资产、分段引用必须全部闭合。

**可机器验证断言**：

- `scripts/validate.js` 检查 `shot_id` 与 `asset_id` 唯一。
- 镜头中的人物、商品、场景、道具和服装引用必须存在于对应资产表。
- 镜头提示词、资产提示词和分段方案不得引用未知 ID。
- Python 严格验证器继续检查交付媒体是否真实存在且 provenance 匹配。

**出处**：首轮严格回归发现历史包存在悬空道具引用；仅通过字段类型验证不足以交接。

**反例（作废条件）**：镜头引用未定义资产、分段引用未知镜头，或同一 ID 重复定义，必须 FAIL。

## 公理 4：媒体路径相对、安全且可追溯

**一句话**：交付媒体只用安全相对路径并带来源。

**可机器验证断言**：

- `scripts/validate.js` 拒绝绝对路径、盘符、反斜杠和 `..` 路径逃逸。
- `materialize_reverse_media.py` 拒绝同一路径映射不同时间戳、路径越界和空文件。
- `validate_reverse_package.py --require-media` 校验每个媒体的大小、哈希和 materialization 记录。

**出处**：本次媒体物化与 provenance 闭环设计。

**反例（作废条件）**：`../outside.jpg`、`C:\\temp\\frame.jpg`、缺失文件或无 provenance 的新媒体，必须 FAIL。

## 公理 5：未知必须披露，空心包不能交接

**一句话**：未知显式披露，核心语义不得留空。

**可机器验证断言**：

- `schema.json` 对动作、提示词、分段、不变量和核心视频描述使用 `minLength`／`minItems`。
- `scripts/validate.js` 拒绝 `TODO`、`TBD`、`PLACEHOLDER` 和尖括号占位内容。
- 看不清或听不清的品牌、价格、功效、台词和文字应进入 `evidence.uncertainties`；验证器只能检查披露字段存在，不能判断视觉事实真假。

**出处**：首轮失败门禁中的“空心结构包”和商业事实幻觉问题。

**反例（作废条件）**：必需提示词为空、动作数组为空、仍含占位符，或用猜测补写不可辨认商业事实，前 3 类必须机器 FAIL，最后一类必须人工复核 FAIL。

## 公理 6：生成方案状态不得冒充可执行

**一句话**：未核实模型的分段不得标记为可执行。

**可机器验证断言**：

- `schema.json` 约束执行状态、目标时长、生成方式和输入素材结构。
- `scripts/validate.js` 要求新包每个分段都有 `execution_plan`，并检查其中的镜头／资产引用闭合。
- `ready` 状态必须同时提供真实供应商、模型 ID、模型适配器、明确生成方式、输入素材和能力核验时间。

**出处**：本次 Agent 原生可视化输出升级新写；用于防止用户界面把历史模型名或待决方案显示成当前可执行配置。

**反例（作废条件）**：缺少 `execution_plan`、引用未知资产，或 `ready` 状态缺少模型与核验时间，必须 FAIL；对应 `scripts/validate.js --selftest` 的 3 条反例。

## 能力边界

零硬错误只表示结构、引用、路径和 provenance 可以交接，不表示最终生成视频达到相似度目标。生成、后期和相似度评分属于独立 Skill。
