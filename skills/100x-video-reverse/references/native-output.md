# Agent 原生输出契约 v2.2

默认交付发生在当前 Codex、Claude Code 或同类 Agent 对话中。`reverse.json` 和包内媒体是持久真源；对话回复是它们的可视化投影，不额外生成离线报告文件。回复用什么载体投影由客户端能力决定（见下节）：`digest.py --format fragment` 产出的内联片段是回复本身的渲染载体、随回复消费，与「可选 HTML 导出」那种独立离线报告不是一回事。

第一层的原则：**用户不打开任何文件就能拿走可复刻的方案，而且一屏能看清主线。** 分段（segment，生成单位）是主组织单位；镜头级明细、四类关键帧、证据链、SHA-256、provenance 和验证统计一律不进第一层——它们留在 `reverse.json`、`validation.json` 和可选 HTML 里，只给一句指路。

## 按客户端能力分层

五块内容契约不变，变的只是载体。**先判断客户端，再选载体；判断不了走 md，不要赌。**

| 客户端 | 载体 | 开关 | 状态 |
|---|---|---|---|
| Codex | 对话内联片段；媒体首页 + 五块 = 六个 tab | `--format fragment` | 片段内容、视频播放与 tab 交互已做真实浏览器验收；内联读取仍以当前客户端实际渲染为准 |
| Claude Code | Artifact | 同 `--format fragment` 产物 | 未验证 |
| 其他 / 判断不了 | 可粘贴 Markdown | `--format md`（默认） | 已实测，**默认路径** |

### Codex 内联片段

```
python scripts/digest.py --out-root <批次根目录> --format fragment --fragment-dir <thread 可视化目录>
```

`--fragment-dir` **必须**指到本轮的 `~/.codex/visualizations/<年>/<月>/<日>/<thread-id>/`：内联指令按裸文件名解析，片段落在别处就解析不到。片段文件名还必须是 ASCII 小写连字符格式；`digest.py` 会自动从包名规范化，并追加稳定路径短哈希与呈现版本号。呈现版本号用于强制客户端读取新版片段，不能删掉或固定回旧值。落错位置时 digest 会打印警告。

交付时严格按 digest stdout 的顺序逐行发引用。单条视频是 1 行；多条视频是批次总览 1 行，再接 N 条视频片段：

```
::codex-inline-vis{file="<文件名>"}
```

> 插件 SKILL.md 写的 `visualize{"path":"<绝对路径>"}` 形态在本机实测三次均不渲染，已弃用。不要加载 visualize skill——渲染是客户端能力，读它只会引入错误语法。

六条硬约束（片段本身由脚本生成，agent 不手改）：

- 指令单独成行，与生成它的那轮回复同轮发出；不加 `"mode":"wide"`。
- 不得称它是 artifact／网页／附件／链接／下载，不得加 Markdown 链接。
- 正文不重复片段已有的数据。单条视频只给一句结论 + 机器包路径；多条视频的成功包总览由 digest 自动生成批次片段，正文只补阶段失败清单和机器包路径。
- 视频片段的首 tab 固定为“原片与帧图”审片工作台：完整时长低码率预览 + 可点击节拍轨 + 折叠的原文件事实证据。桌面端的竖屏原片列只占播放所需宽度，剩余空间给多列帧板；不得把 9:16 视频放进占据大多数页面宽度的空黑舞台。窄屏才改为上下结构和横向帧轨。点帧时暂停并定位到该帧时间，同时显示该镜头所属生成分段的完整提示词；必须明确提示词生成单位是分段，不得伪称存在逐镜头提示词。播放时按镜头起止时间同步高亮当前节拍并更新已打开的提示词；每个节拍只用 1 张包内已验证帧。展示预览不是真源，原文件路径和 SHA-256 仍以 `source_manifest.json` 为准。
- 多条视频不能合成一个重片段。必须是“1 个带每条首帧、顺序号和包名的轻量批次总览 + N 个彼此独立的视频片段”，每条详情继续显示「第 N／M 条」，资产、提示词和结论不跨包复用。相同源文件名必须靠包名与编号区分。
- 单个视频片段仍受 1 MB 上限约束。生成器先为帧图计费，再按剩余预算自适应压缩完整时长视频；无法容纳时明确降级为帧图，不截断视频。基础帧图本身超限时再调小 `--thumb-width`，仍超就整批落回 `--format md`。

### Claude Code：Artifact（未验证）

载体是 Artifact，不使用 `::codex-inline-vis`，限额 16 MB。**这条路径没有实测**：首次走它时当场确认渲染结果，确认不了或渲染不对就落回 `--format md`，不要按已跑通交付。

### 其他客户端：Markdown（默认）

`::codex-inline-vis{...}` 是 Codex 客户端协议，别处不解析、会显示成一行怪文本。所以判断不了就走 md——md 在哪都能读，赌错的代价是用户拿到一行乱码加一个打不开的路径。下一节的媒体降级规则只管 md 路径；片段的媒体是内嵌 base64，不受其约束。

## 客户端适配

本节只管 `--format md` 路径；fragment 路径的媒体是片段内嵌的 base64 缩略图和压缩 MP4 预览，不受这里约束。

- 源视频与图片用客户端原生能力直接内联展示：Codex 桌面端使用绝对本地路径的 Markdown 媒体语法，不要写 `file://`；**路径写正斜杠**——反斜杠在链接目标里是 Markdown 转义符，按渲染器不同会丢分隔符。其他客户端使用其等价的本地预览能力。不能内联时给出可点击绝对路径并说明限制：跑 `digest.py --host terminal`，它按这条统一降级并保持五块不变，不要手改图片语法。不得因此自己去写 HTML——需要更强载体时按上节走 `--format fragment` 或 Artifact，那是脚本产出、有明确契约的片段；手搓网页任何情况下都不允许。
- 只展示包内已验证媒体，不引用临时抽帧或已过期修订。
- 长提示词用代码块；结构、时长和建议用紧凑 Markdown 表格。不把完整 JSON、哈希清单或 provenance 倾倒进回复。

## 第一层固定五块

1. **一屏结论**：视频骨架（hook → 产品桥接 → 证明/展示 → 收尾，用一行话概括每步）、总时长与节奏（节拍数/硬切密度）、有无口播、有无字幕/屏幕文字、整体风格一句话；附可播放源视频与包根目录路径。验证状态压缩成一行（通过/警告数），不展开统计。
2. **分段复刻表**：按时间顺序，每段一行表格（段号、时间范围、叙事作用、执行状态、模型、生成方式、目标时长），随后逐段给出 1–3 张关键帧（段首帧 / 段内最强高光帧 / 段尾帧，从该段镜头的 frames 里选）+ 该段完整生成提示词（代码块，按 `execution_plan.model_adapter` 选择已有版本；未选 adapter 时回退到 Omni 版并如实显示）。`needs_model_selection` 和 `blocked` 不得写成可执行，是否生成、用哪家由用户继续决定。
3. **资产**：人物 / 产品 / 场景各展示 1 张最清晰截图 + 一致性提示词（代码块）+ 禁变项（invariants + must_not_change 中与该资产相关的条目）。道具、服装、音频、文字资产只列 ID 和一句话，明细留在包内。
4. **文字层**：屏幕字幕/文字逐条表格（时间范围 + 逐字原文 + 位置/样式一句话），说明"文字由后期叠加，不进生成提示词"。没有文字时写"未观察到屏幕文字"。
5. **音频**：口播逐字稿（有则逐条列出，带时间）；没有口播时说明；音乐氛围一句话（节奏/情绪/有无人声）。frames-only 模式下如实写"音频未分析：本次没有音频语义通道"——不要写成「无 GEMINI_API_KEY」，因为用户主动要求纯本地时也会走这条路。

五块之后只允许两小节收尾：**限制与不确定项**（uncertainties/limitations 择要，含验证警告里用户必须知道的条目）和**机器包路径**（`reverse.json`、`validation.json`、包根目录的可点击绝对路径）。

## 多条视频

一次反推多条时，先给一段批次总览再逐条展开：一张表列出每条视频的文件名、时长、节拍数、分段数、验证状态和警告数；失败的条目在同一张表里写明失败原因，不要省略也不要挪到末尾。

随后逐条交付完整的五块，按用户给出的顺序排列，每条以视频文件名开头。不要把多条视频的分段表合并成一张，也不要用一条的资产、提示词或结论代指另一条——它们是彼此独立的包。客户端有单次响应上限时，先给批次总览，再按视频逐条续发，明确标注「第 N／M 条」。

以上是 md 路径的形态。fragment 路径下，digest 自动生成 1 个只含每条视频 1 张首帧的轻量批次总览片段，再为每条成功视频生成 1 个独立片段；总览与详情共享编号，按 stdout 顺序发出全部引用行，**不给每行加文件名标题**——总览已经点名，再加就是重复。阶段一或 `--finalize` 失败、因而没有 `reverse.json` 的条目不在 digest 总览中，必须在正文单列原始失败原因，不能静默省略。

## 控制回复体积

- 每段关键帧最多 3 张；同段提示词只出现一次；重复观察事实合并成一句。
- 不展示镜头级三帧矩阵，不展示四类关键帧全集，不列成本表（本 skill 无生成调用；外部分析 token 用量写进 provenance，不占第一层）。
- 段很多时按顺序分批交付，明确"第 N/M 部分"，不牺牲时间顺序。
- 用户只要求局部审计时，只展示范围内内容，并明确这是局部视图。

## 可选 HTML 导出

只有用户明确要求网页、HTML、离线报告、打印版，或要求交给不能使用 Agent 客户端的人员打开时，才读取 `visual-report-design.md`，运行 `render_visual_report.py` 并加 `--require-review` 验证。HTML 是可删除、可再生的导出物，承载镜头级全量明细，不进入默认完成标准，也不能成为下游 Skill 的输入真源。

这里的 HTML 指 `render_visual_report.py` 的独立离线导出物，与 `--format fragment` 的对话内联片段不是一回事：片段是回复的渲染载体，只承载媒体首页与第一层五块、随回复消费，不承载镜头级全量明细，也不能拿去交给打不开 Agent 客户端的人。用户要离线报告时仍然走 `render_visual_report.py`，不要把片段文件当报告发出去。
