# 标准工作流

## 1. 建立只读源基线

- 确认输入是单个本地视频，扩展名为 `.mp4`、`.mov`、`.webm`、`.mkv` 或 `.m4v`。
- 计算 SHA-256，记录文件大小、时长、比例、分辨率、FPS、编解码器和音轨。
- 不重编码、不改名、不移动源文件。每次运行使用新的包目录。

## 2. 提取确定性证据

运行 `prepare_evidence.py`。它生成三类互补信号：

1. 高阈值场景变化：减少误报，定位明显硬切。
2. 敏感场景变化：召回短镜头、闪切和快速产品动作。
3. 均匀时间采样：避免检测器漏掉无硬切但语义变化的动作。

证据帧覆盖切点前后、动作过程和全片时间轴。检测器输出只能叫 `cut_proposals`；最终镜头边界必须结合完整视频、帧序列、音频、字幕和叙事语义校正。

## 3. 做多模态语义校正

优先同时输入完整视频和本地证据摘要。模型只能使用当前可见、可听证据：

- 精确到毫秒的镜头起止时间；镜头应覆盖全片，不重叠、不留无解释空隙。
- 四类关键帧：起始、代表、高光、结束。高光应选择动作峰值、商品首次出现/使用、人物表情变化、证明过程或 CTA，而不是机械中点。
- 逐镜动作顺序、产品交互、景别、机位、运镜、光线、色彩、口播、音乐、音效、字幕和屏幕文字。
- 对听不清、遮挡、反光、压缩模糊或可能误读的内容降低置信度，并写入 `uncertainties`。

如果外部模型不可用，仍保留完整本地证据包并报告阻塞，不用旧模型静默替代用户指定模型。

## 4. 建立资产和连续性图

资产 ID 跨镜头稳定。每个资产记录首次出现、出现镜头、可观察事实、一致性锚点、截图、裁剪建议、通用提示词、模型适配提示词、禁止变化项和置信度。

一致性锚点只写可复核特征，例如颜色、材质、形状、相对位置、服装和包装文字。不要把推断的品牌故事、功效、规格、年龄、身份或商业结果写成事实。

## 5. 形成下游提示词包

- 全局提示词：整体风格、节奏、人物/产品/场景关系和不变量。
- 镜头提示词：动作先后、时间节点、镜头语言、表演、音频和文字。
- 资产提示词：稳定外观和禁止变化项。
- 模型适配版本：只根据已核实的当前输入能力调整语法和分段，不发明能力。
- 分段方案：按镜头和叙事边界分组；模型时长上限仅作为兼容约束。
- 拼接说明：尾帧锚点、源音频、字幕/OCR 和确定性后期需求。

## 6. 物化和验证

`reverse.json` 中所有相对路径以该文件所在目录为基准。运行 `materialize_reverse_media.py` 抽取镜头帧和资产截图；它拒绝路径越界、同一路径对应不同时间戳和空文件。已有非空媒体只有在 `materialization_manifest.json` 中的源哈希、请求时间戳和文件哈希均匹配时才跳过；无 provenance 或不一致时必须换新修订目录，不能信任或覆盖。先物化媒体，再运行验证器。处理顺序：

1. 修复 Schema 和缺字段。
2. 修复时间轴覆盖、镜头重叠、未知引用和缺失媒体。
3. 检查分段过长、置信度、不确定项和连续性警告。
4. 人工回看至少每个镜头的起始、高光和结束证据。

## 7. 交接

`report.md` 只写已验证事实：源哈希、规格、镜头/资产/证据数量、验证结果、限制、不确定项和建议交给哪个下游 Skill。不得把反推分数写成克隆分数，也不得声称已生成视频。

## 用户反馈迭代

将反馈拆成“时间点/镜头、对象、观察到的问题、期望修正、影响字段”。用户对相似度、节奏或观感的判断属于修正依据，不等于源片客观事实。为每轮反馈创建新的修订目录，复用未变化的源证据，只更新受影响的镜头/资产/提示词；随后重新物化必要媒体并运行完整验证。不要覆盖上一轮包，也不要因局部反馈顺手重写无关镜头。
