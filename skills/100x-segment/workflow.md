# 100x-segment · 三阶段流程

> 本 skill 采用三阶段流程（Phase 1 接收与校验，Phase 2 三层生成与自检，Phase 3 分级返工）。输入为纯文本口播脚本，进行纯文本层面的分段与气口标注。

---

## Phase 1 · 接收 + 校验

### 触发进入条件
- 用户直接调用 `/100x-segment`
- 或被入口路由（如未来的 `/100x-tiktok`）转来
- 或自然语言触发："帮我分段" / "这条脚本怎么分段" / "拆一下这条口播文案" /
  "segment this script" / "break this voiceover into beats"
- 或直接给一段口播脚本纯文本，要求"按模块拆" / "标一下气口" / "这段哪里该喘气"

### 固定开场白（≤60 字，实测 40 字）
> 我是分段器。发口播脚本纯文本(英语/西语)，给你模块+原型+镜头目的+气口标记。

**说话锁定**：不加"你好"/"欢迎使用"/"请问"；不主动列本 skill 能做什么/不能做
什么；不提其他 skill。

### 输入分级校验（按顺序执行）

```
1. 读取 source_text
   ├─ 为空/未提供 → 类别 A 缺失，见下方"类别 A 拒绝模板" → 终止
   └─ 非空 → 进入 2

2. 语言检测（从 source_text 本身推断，不是问用户要的独立输入项）
   ├─ 判定为英语 → language="en"，进入 4
   ├─ 判定为西语 → language="es"，进入 4
   └─ 判定为其他语言，或英西混杂到无法判定主语言 → 见下方"语言范围拒绝模板" → 终止

3. （无此步骤——本 skill 只有 1 项类别 A 必填字段，见下方"类别 B 说明"）

4. 类别 C（上游可选产出）
   ├─ 本仓目前没有任何"产品画像/选题材料"类 skill 产出可作为上游 → 静默跳过，
   │  不提示、不要求用户先跑别的 skill
   └─ 若未来上游 skill 存在且用户主动提供了产出 → 读入作为 Phase 2 的语境参考
      （例如已知的品类/受众信息可以帮助 module 识别更准，但不是必需）
```

### 类别 A（硬性必填）：`source_text`

`source_text` 是本 skill 唯一的硬性必填输入——一段口播脚本/文案纯文本。缺失时
的固定拒绝话术（不代猜、不接受视频文件替代、不推荐先跑别的 skill）：

```
100x-segment 需要一段口播脚本的纯文本。没有文本无法分段——请把脚本贴过来。
```

### 类别 B（软性输入）：无

本 skill **没有类别 B 软性字段**。`source_text` 本身已经包含分段所需的全部信号
（模块识别、原型判断、镜头目的预判、气口位置全部从文本本身的措辞和标点推断），
不需要用户额外补充卖点/受众/语气这类外部信息才能开始工作——这一点和
`100x-persona`（`source_script` 是唯一输入，同样没有类别 B）结构一致，和
`100x-search-query`（`category`/`core_benefit` 等类别 B 三级降级）不同，因为
后者的输出（搜索词）本质上需要"品类/卖点"这类结构化上下文，而分段任务不需要。

### 语言范围（明确边界，不是类别 B 降级）

`language` 不是问用户要的输入，是从 `source_text` 本身检测出来的——但检测结果
只接受 `en`/`es` 两种（`schema.json` 的 `language.enum` 硬锁），这是因为公理3/4
的气口强弱判据（转折连词表、填充词表、一口气上限）目前只锁定了这两种语言的判据，
其他语言没有对应判据可用。检测到其他语言时的固定拒绝话术：

```
100x-segment 只支持英语和西语脚本的气口判据。这段文本看起来不是英语或西语，
本 skill 暂时无法处理——如果这是英西混排，请只发其中一种语言的完整版本。
```

这不是"文字降级"（没有视频用文字替代那种降级），是**输入语言种类本身超出本
skill 已定义的判据范围**——参照 `100x-hook` "只输出英语，无例外"的边界
处理方式，直接拒绝，不猜、不代做、不推荐路由。

### 退出信号
`source_text` 非空 + `language` 已判定为 `en`/`es` 之一 → 进入 Phase 2。

### 失败处理
| 失败类型 | 行为 |
|---|---|
| 类别 A 缺失（无文本）| 输出固定拒绝话术 → 终止。不询问、不路由、不降级 |
| 语言判定超出 en/es 范围 | 输出语言范围拒绝话术 → 终止。不询问、不路由 |

## Phase 2 · 三层生成 + 自检 + 渲染

分 4 个子步骤：**2A 段落切分 → 2B 镜头目的预判 → 2C 气口标注 → 2D 自检+渲染**。
三层（L1/L2/L3）是独立叠加的视角，2A/2B/2C 分别产出，2D 统一校验后一次渲染
（自检和渲染合并，参照 `storyboard` Phase 2 的先例："两者没有独立 I/O，
自检过就渲染，合并降低心智负担"）。

### 子步骤 2A · 段落切分（L1：segments[]）

**切分判据（任一触发即开新段）**：
- 叙事功能明显切换（例如从"痛点铺垫"切到"成分讲解"）
- 出现新模块的典型 seed 措辞（见下方"10 模块识别词典"）
- 阶梯时间线内部的"Day X / Week X"节点变化（仍算同一 `staged_timeline` 段，
  除非叙事功能整体切换到别的模块）

**不应切分**：
- 同一模块内部换了个说法但功能没变（比如同一个痛点用两句话反复强调）
- 纯粹为了让每段变短而机械切断一个完整语义单元

**10 模块识别词典**（读取 module 时对照，完整版见口播文案蓝图规范 §2 表格）：

| module 值 | 识别信号（不是穷举，供快速定位） |
|---|---|
| `hook` | 誓言型/悬念提问/重大新闻式开场/警告反向/统计冲击/条件假设结果 |
| `authority` | 从业年限/身份背书/机构名/名人背书/"as a [身份]"句式 |
| `pain` | 痛点词堆叠（apron belly/love handles 类）/圈定人群（"if you're a..."） |
| `mechanism` | 成分名/机制解释/"this helps your body do X" |
| `staged_timeline` | Day/Week 节点递增 + 效果量化描述 |
| `dosage` | 用量说明/反向神秘化（"do NOT take too much"） |
| `risk_reversal` | 退款承诺/"no results in X days" |
| `scarcity` | 库存/名额/时限措辞 |
| `price_anchor` | 价格对比（vs 手术/vs 原价）/具体金额 |
| `cta` | 点击/购买指令/链接位置指令 |

**module 11（Localization 本土化表达）不进 `segments[].module` 枚举**——它是
贯穿全篇的风格维度（美式俚语/具体品牌措辞/`$`/`lbs` 这类本地化单位），识别时
留意但不单独成段（见 `axioms.md` 公理1）。

**archetype 判定**：全篇切完段落后，对照口播文案蓝图规范 §3"7 原型骨架"，比较整体模块排列顺序最接近
A-G 哪一个骨架；如果同时明显叠加了另一个原型的手法（例如反转逆向心理型 E 的
"别喝太多"警告式措辞），标成"主+辅"复合（如 `"G+E"`），主骨架在前。

**输出**：`segments[]` 数组，每项含 `segment_id`（从 1 连续递增）/`module`
（10 值之一）/`raw_text`（该段原文，逐字摘自 `source_text`）/`text_annotated`
（此步骤先原样等于 `raw_text`，气口标记留到 2C 再加）。

### 子步骤 2B · 镜头目的预判（L2：shots[]）

**目标**：给每个（或每组）段落预判一个 `shot_purpose`（7 枚举标准定义），供未来真正处理视频画面的 skill 参考——本 skill 不吃
视频帧，这里只是"从文字判断这段大概率该是哪种镜头意图"，不是真正的镜头切分。

**module → shot_purpose 参考映射（启发式，非硬规，允许创作判断突破）**：

| module | 常见 shot_purpose |
|---|---|
| `hook` | `hook` |
| `authority` / `pain` | `build` |
| `mechanism` | `reveal` |
| `staged_timeline` / `dosage` | `demo` |
| `risk_reversal` / `scarcity` / `price_anchor` / `cta` | `cta` |

**允许合并/拆分**：一个 `staged_timeline` 段落如果内部有 3 个时间节点，可以
拆成 3 个 `shot_item`（`segment_refs` 各自只含该段 `segment_id`，用同一个
`segment_id` 出现在多个 shot 里）；反过来几个短段落（比如
`risk_reversal`+`scarcity`）如果预判会是同一个镜头一次带过，可以合并成一个
`shot_item`（`segment_refs` 含多个 `segment_id`）。

**硬约束（公理4，2D 阶段校验）**：`shot_id` 从 1 连续递增；`segment_refs` 里
每个数字必须是真实存在的 `segment_id`；每个 `segment_id` 必须被至少一个
`shot_item` 引用（零孤儿）。

### 子步骤 2C · 气口标注（L3：行内标记）

对每个 `segments[]` 项的 `raw_text`，按 `axioms.md` 公理3的优先级顺序逐句/逐
分句判定气口，写入同一项的 `text_annotated`：

```
1. 断点后紧跟转折连词（EN: but/so/and then；ES: pero/entonces/y）→ 强 ‖
2. 断点前是句末标点(.!?)或破折号(—) → 强 ‖（且这是强制出现，句子没走到段尾
   之前，句末标点后必须有气口标记）
3. 断点前是逗号/分号，且未命中上面两条 → 弱 ·
4. 一口气超过上限（EN 14 词 / ES 16 音节估算）且中间没有任何标记 → 必须补一个
   气口（强弱不限，看是否命中 1-3 条）
5.（软性）填充词（EN: like/okay so/wait；ES: o sea/bueno）后面建议补一个气口
```

**额外软性提醒（不阻塞，但建议自查）**：价格/数字前的强调停顿不是呼吸停顿，
不要在价格数字前标气口——例如"$29"前面如果有停顿感，那是**强调**不是**呼吸**，
不应该出现 `‖`/`·`。

**`source_text` 本身缺乏标点时的生成期指引（已知局限，非
机器可验证）**：以上判据全部锚定在真实标点字符（逗号/分号/句末标点/破折号）
上。真实 ASR 转写文案有时整段几乎没有句末标点，只能靠大写字母开头猜句子
边界（在部分真实口播语料中可能遇到这种情况）。遇到这类输入时：2A 切分段落、2C 标气口都仍按"叙事功能/语义边界"
判断，把明显的大写单词开头/语气停顿处当成事实上的句子边界来标气口，不因为
"原文没有标点"就放弃标注或干脆不标。**但这条只是生成期的人工判断建议，
`scripts/validate.js` 的 mandatory-presence 判据（公理3）只认真实标点字符——
这段文本天生不会触发任何"强制补气口"的报错，哪怕完全不标气口、只要音节
上限满足，产出依然会通过校验。** 这是"判据锚定在标点符号"这个设计选择在
"输入本身没有标点"场景下的已知覆盖空白，不是一个可以升级成公理的判据（没有
可字符串化的"这里该不该是句子边界"规则），已同步记入 `axioms.md` 公理3 TODO。

**标记格式**：气口字符必须单独用空格前后隔开（如 `"...fast. ‖ Then..."`），
不能紧贴文字（如 `"...fast.‖Then..."`）；`text_annotated` 不能以气口字符开头或
结尾；两个气口字符之间必须有实际文字，不能紧挨。

**红线（公理2）**：`text_annotated` 只能**新增**气口字符，不能删词、加词、改
词、调换词序——去掉所有气口字符、空白归一化后，必须与 `raw_text` 逐字相同。

### 子步骤 2D · 自检 + 渲染

自检和渲染合并（参照 `storyboard` Phase 2 先例）。全部通过后立即渲染，
不另外询问。

**硬性自检（对应公理，任一失败必须定位重做，不允许直接输出）**：

| # | 检查 | 对应公理 | 失败处理 |
|---:|---|---|---|
| S1 | `module` 在 10 值枚举内 | 公理1 | 重判该段 module |
| S2 | `archetype` 匹配 `[A-G]` 或 `[A-G]+[A-G]`（两字母不同） | 公理1 | 重判archetype |
| S3 | `text_annotated` 去标记后逐字等于 `raw_text` | 公理2 | 定位被改动的段，逐字核对修回 |
| S4 | 气口强弱按优先级判据正确（转折>句末/破折号>逗号）| 公理3 | 定位该气口标记，改强弱 |
| S5 | 每个气口区间未超语言对应的一口气上限 | 公理3 | 该区间补气口 |
| S6 | `shot_purpose` 在 7 枚举内 | 公理4 | 重判该 shot |
| S7 | `segment_id`/`shot_id` 从 1 连续递增 | 公理4 | 重新编号 |
| S8 | `shots[].segment_refs` 全部指向真实 `segment_id`，且全部 `segment_id`
     都被覆盖（零孤儿）| 公理4 | 补齐引用或新增缺失的 shot |

**软性自检（警告不阻塞，写进 `meta.warnings`）**：
- [ ] 填充词后有没有漏标气口
- [ ] 有没有气口标记落在价格/数字前面
- [ ] `archetype` 若为复合，主骨架是否真的排在前面（正则查不出语义，需人工判断）

**全部硬性自检通过 → 立即渲染**：

产出 1（内部 JSON，形态 A，`schema.json` 定义的 `SegmentBundle`）：包含
`source_text`/`language`/`archetype`/`segments[]`/`shots[]`/`meta`。

产出 2（外部 Markdown 表，形态 B，可选，人读用）：

```markdown
## 设定
- 语言：{language}
- 原型：{archetype}

## 段落表

| 段号 | 模块 | 原文(含气口标记) | 镜头目的 |
|---|---|---|---|
| S1 | hook | You know what your afternoon slump is actually scared of? ‖ Not coffee, · not a nap, · not another snack. | hook |
| S2 | authority | Twenty years in sports recovery taught me one thing about tired bodies. | build |
```

7 列/4 列不是重点，重点是"JSON 和 Markdown 是同一份数据的两种形态"——渲染器
从 JSON 一次产出 Markdown，不分别生成（同 `storyboard` 公理3 纪律）。

### Phase 2 退出信号
S1-S8 全部通过 ✓ → 产出双形态给用户，进入等待（可能触发 Phase 3 返工）。

### 失败处理
| 失败类型 | 行为 |
|---|---|
| 硬性自检 S1/S2/S6/S7/S8 未过 | 定位到具体段/镜头重做，不整体推翻已过的其他项 |
| 硬性自检 S3/S4/S5 未过 | 定位到具体气口标记修正，不重新切分段落 |
| 软性自检未过 | 不阻塞，`meta.warnings` 记录，用户自行判断是否返工 |

## Phase 3 · 返工（用户触发，非必经）

返工粒度直接对应三层（L1/L2/L3），触发词决定动的是哪一层：

| 触发词 | 返工层 | 动作 |
|---|---|---|
| "这段模块不对" / "原型选错了" / "重新分段" | L1 | 重做 `segments[]`（module/archetype），
  L2/L3 里引用受影响段落的部分跟着重算，未受影响的段落保留 |
| "这个镜头不对" / "这两段应该合成一个镜头" | L2 | 只重做 `shots[]`，`segments[]` 和
  各段的 `text_annotated` 不动 |
| "这里的气口不对" / "这句该停顿" / "这个逗号后面不该强停" | L3 | 只重做该段
  `text_annotated`，`module`/`shot_purpose` 不动 |

**返工上限**：
- L3 单段气口微调：无上限（用户反复调整是正常的）
- L2 单镜头调整：同一 shot 3 次未过自检 → 保留最佳版 + `meta.warnings` 加
  `"shot_id=N 返工3次未过，建议人工判断"`
- L1 整体重分段：2 次未过 → 提示（不点名要求先跑其他 skill）：
  ```
  分段 2 轮重来仍不通。常见原因是脚本本身叙事结构不够清晰（模块之间界限模糊）
  或脚本混了多种语言。可以：（1）把脚本改得更结构化一点再试 （2）如果是多语言
  混排，只发其中一种语言的完整版本。
  ```

**不允许的返工路径**：
- ❌ 用户说"气口太多了" → 直接删掉整段标记而不重新判定优先级（会破坏公理3的
  强制出现规则，比如句末标点后必须有强气口）
- ❌ 用户说"镜头数太多" → 机械合并 shot 但没检查合并后 `segment_refs` 是否还
  完整覆盖（会破坏公理4零孤儿规则）
- ❌ 用户说"帮我加个 emotion 字段" → 这是修 `schema.json` 的请求，不在本
  skill 生成层处理（回答："`shots[]`/`segments[]` 目前不含情绪字段，这个信息
  可以留在段落的 `raw_text` 本身里；如需独立结构化字段，需要另外评估 schema
  改动"）

### 退出信号
用户确认满意（"行"/"可以"/"这版OK"）或直接使用产出无后续反馈 → Phase 3 结束。

---

## 流转图

```
[用户触发]
  ↓
Phase 1 接收+校验（source_text 必填 → 语言检测 en/es → 类别C静默跳过）
  ↓ 通过
Phase 2
  2A 段落切分(L1: module+archetype)
    ↓
  2B 镜头目的预判(L2: shot_purpose，与 2A 允许合并/拆分)
    ↓
  2C 气口标注(L3: 行内标记，压进每段 text_annotated)
    ↓
  2D 自检(S1-S8)+渲染(JSON + 可选 Markdown)
  ↓
  ├→ 满意/无回复 → END
  ├→ 返工触发词 → Phase 3（L1/L2/L3三层分级，对应触发词表）
  └→ L1 整体返工 2 次不过 → 提示常见原因，不点名路由
```
